# Albom — правила для Claude

Локальный, некоммерческий фоторедактор (см. README.md). Чистый client-side
JS (без сборки/фреймворка) + OpenCV.js + Leaflet + маленький `server.py`
только для одного эндпоинта («открыть папку в Проводнике»). Никакого
бэкенда с данными, никакой отправки фото куда-либо.

## Правила интерфейса

- **Ничего не скрывать — только делать неактивным.** Если для
  кнопки/строки параметров нет данных или возможности, она остаётся
  видимой, но получает `disabled` (кнопки) или блёклый плейсхолдер вида
  «—» (текстовые строки), а не `hidden`. Это касается всего приложения
  одинаково (панель параметров, кнопки карты и т.д.) — раньше уже было
  по-другому в одном месте, и это осознанно исправлено.
- **Общие элементы управления — один CSS-класс, а не точечные
  переопределения** для каждого места, где они встречаются.

## Правила для новых геометрических инструментов

Любой новый инструмент трансформации (поворот, перспективная/линзовая
коррекция и т.п.) должен по-настоящему деформировать пиксели — варпить
всё изображение в canvas того же размера, с пустыми/прозрачными
областями там, где не хватает исходных данных (как уже делает поворот),
— а не рисовать оверлей поверх выбранной области. Финальную
прямоугольную обрезку всегда делает уже существующий общий инструмент
кадрирования (`State.cropRect`, селектор пропорций, `exportCrop`) —
новый инструмент не должен строить собственный quad-based
select+crop+export путь.

## Тестирование

Использовать skill `webapp-testing` (Playwright). Приложение — чистый
статический сайт, поэтому достаточно локального HTTP-сервера в корне
репозитория (тестовый порт — не 8642, он занят «боевым» сервером
пользователя). Если сервер однопоточный (`python -m http.server`),
конкурентные `fetch()`/`page.reload()` в тестах могут ловить `Failed to
fetch` или подвешивать reload — использовать многопоточный сервер
(`ThreadingHTTPServer`/`socketserver.ThreadingMixIn`) и звать
`page.wait_for_load_state("networkidle")` перед `page.reload()`.

Лента миниатюр — всегда прямые дети `#album-grid`: один горизонтальный
ряд в нижнем режиме; в боковом — столбцы через flex-wrap (не CSS
`column-width` — тот сам растягивает столбик шире заданного, чтобы не
было пустого места, отчего миниатюры переставали уменьшаться при
сужении панели), ширина миниатюры фиксирована (3см), высота — своя,
настоящая, без выравнивания. Если по ширине помещается только один
столбец, `updateColumnMode()` в app.js переключает боковую ленту в
`.single-column` — обычный список с вертикальной прокруткой вместо
обрезанной сетки со столбцом-недомерком; колесо мыши и
`highlightActiveThumb()` учитывают этот переключатель, чтобы листать
по правильной оси. Любая новая навигация по сетке (фото или варианты
цвета) должна опираться на `findGridNeighbor()` в app.js.

## Тесты и координаты канваса в режиме перспективы

В режиме перспективы `#photo-canvas` в CSS больше не совпадает 1:1 с фото:
`perspectiveCanvasMargin()` резервирует отступ вокруг фото (чтобы ручку
угла можно было тянуть за пределы кадра и она не обрезалась по краю
канваса). Поэтому в Playwright-тестах, кликающих по экранным координатам
ручек, нельзя считать `scale = canvasBox.width / previewW` и точку (0,0)
= левый верхний угол канваса — нужно явно прибавлять
`margin.left/top * State.previewZoom` к позиции канваса, иначе клик
попадает мимо ручки в пустой отступ и тест молча не находит эффекта от
перетаскивания.
